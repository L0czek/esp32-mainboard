# defmt MQTT WASM demo

This is a deliberately small example website that shows how to use the Rust decoder from plain
browser JavaScript.

The page does not connect to MQTT. Instead, it demonstrates the exact frontend-facing contract:

1. load the firmware ELF bytes
2. create `new DefmtDecoder(elfBytes)`
3. pass each MQTT payload to `decodeChunk(payloadBytes)`
4. render `result.lines` and `result.warnings`

## Files

- `index.html`: the demo page
- `main.js`: plain JavaScript integration with the generated WASM package
- `styles.css`: lightweight styling
- `pkg/`: generated by `wasm-pack build`; not committed

## Build the WASM package

Run these commands from the decoder crate:

```sh
cd tools/defmt-mqtt-decoder
RUSTFLAGS='' wasm-pack build --target web --out-dir example-web/pkg
```

That command does two things:

1. compiles the Rust crate for the `wasm32-unknown-unknown` target
2. generates the JavaScript glue file that the browser imports from `example-web/pkg/`

After that, serve the example over HTTP:

```sh
cd tools/defmt-mqtt-decoder/example-web
python3 -m http.server 8080
```

Then open `http://127.0.0.1:8080`.

## How the JS integration works

The demo uses the generated package like this:

```js
import init, { DefmtDecoder } from "./pkg/defmt_mqtt_decoder.js";

await init();

const decoder = new DefmtDecoder(elfBytes);
const result = decoder.decodeChunk(mqttPayloadBytes);

console.log(result.lines);
console.log(result.warnings);
```

`DefmtDecoder` is stateful. Keep the same instance alive while processing the MQTT stream so split
frames can be completed across multiple payloads.

## Using the raw WASM target directly

If you want to work with the raw `wasm32` target artifacts instead of `wasm-pack`, the flow is:

```sh
cd tools/defmt-mqtt-decoder
RUSTFLAGS='' cargo build --target wasm32-unknown-unknown --release --lib
wasm-bindgen \
  --target web \
  --out-dir example-web/pkg \
  target/wasm32-unknown-unknown/release/defmt_mqtt_decoder.wasm
```

Why the extra `wasm-bindgen` step matters:

- `cargo build --target wasm32-unknown-unknown` gives you the raw `.wasm` binary
- browser JavaScript still needs a small generated wrapper so it can call exported Rust functions
  ergonomically
- `wasm-pack` is the simplest way to do both steps together
- `wasm-bindgen-cli` is useful when you want to keep the target build and JS glue generation as
  separate steps

## Feeding MQTT payloads into the decoder

In a real frontend, your MQTT client would already hand you raw payload bytes. The only thing your
JS code needs to do is convert those bytes into a `Uint8Array` and pass them through:

```js
const payload = new Uint8Array(message.payloadBytes);
const result = decoder.decodeChunk(payload);
```

Append `result.lines` to your log view, and surface `result.warnings` if you want visibility into
recoverable malformed frames.
